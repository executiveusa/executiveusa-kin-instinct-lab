# KIN Case Study Template

## PERSON
Minimum identifying information necessary.

## PROBLEM
Concrete pre-deployment problem.

## CONFIGURATION
Persona, permissions, tools and boundaries.

## ACTION
What the agent actually did.

## RESULT
What changed.

## EVIDENCE
Independent support for the result.

## FAILURE
What failed, confused the user, required intervention, or created risk.

## LESSON
What changes before the next deployment.

## Verification gate
- [ ] Real task 1 completed + evidenced
- [ ] Real task 2 completed + evidenced
- [ ] Real task 3 completed + evidenced
- [ ] Owner confirmed outcome/usefulness
- [ ] Failures recorded
- [ ] No unsupported safety/sovereignty claims

Only then mark **VERIFIED**.
